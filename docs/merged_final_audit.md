## Defects fixed

### Input and calendar consistency

- Reject duplicate assignment rows, including duplicates that previously
  disappeared during conversion or set comparison at publication.
- Reject invalid day/period coordinates rather than mapping them into another
  valid day.
- Check teacher, student-group and room collisions when restoring canceled
  classes, assigning cover and accepting teaching requests. Validate room type,
  availability and the combined strength of shared atomic groups.
- Enforce daily and dated weekly teaching limits for extra classes and
  substitutes. Weekly counts use active Monday–Sunday teaching periods, release
  canceled occurrences and do not count a replaced occurrence twice.
- Keep holiday, assessment and quiz cancellation/restoration consistent, and
  reject stale ownership and disruption versions.
- Mark an optimization job complete only after its saved result is available.

### Optimization and numerical correctness

- Carry the complete evaluated archive between increasing disruption epsilon
  caps, rather than dropping candidates when the archive exceeds population size.
  Archive carry-over does not consume new full evaluations.
- Convert CP-SAT epsilon limits with floor in exact integer units so a returned
  solution cannot exceed a requested cap through rounding. State the two-objective
  scope of the reference model accurately.
- Distinguish ordinary Tchebycheff from augmented Tchebycheff scalarization, honor
  AMOSA's configured cooling factor, and describe the latter as AMOSA-inspired.
- Validate MCDM inputs, weights, AHP consistency and numeric scaling; correctly
  handle zero-weight endpoints and sensitivity calculations.
- Apply the existing exact Pareto postprocessor to website fronts and comparison
  archives. Preserve native run records, publish traceable derived exact fronts,
  and flag optional-method invalid results as failures.
- Validate generator session parameters before arithmetic and save a canonical,
  replayable resolved configuration. All stored default data remain identical.
- Restrict stochastic repair tie-breaking to infeasible candidates, and reject
  malformed or tampered cached comparison histories and archives.

### Frontend and installation

- Render imported non-clock period labels and zero/multiple lunch periods safely.
- Clear or isolate stale availability, calendar drawer, optimization and decision
  responses. Show publication, leave and export failures accurately.
- Make notification actions reachable and mobile navigation accessible by name.
- Show recorded convergence samples and measured disruption/proof information.
- Include the already-required web/test dependencies in the pinned lock, so the
  documented clean installation can run the complete suite.
- Make the PowerShell demo stop on native-command failure and explain its missing
  environment prerequisite. The equivalent Python commands passed; native
  PowerShell itself was unavailable on this Linux audit machine.

### Scientific claims and provenance

- Correct finite-grid support claims: failure to find a point with a particular
  weight grid is not a proof that it is unsupported.
- Separate weighted-sum scalar optimality, two-objective CP-SAT references and
  non-domination among saved candidates from global three-objective optimality.
- Correct statistical interpretation and supplementary algorithm labels, update
  references, and rebuild the report/slides with the corrected wording.
- Restore the historical verifier after merged extensions changed live package
  hashes. It still verifies every recorded snapshot hash, reports live drift and
  refuses drift in the model, evaluator or metrics used for revalidation.

## What the experiment checks establish

The primary historical and held-out **measurements were revalidated, not
recomputed or replaced**. All 2,619 tracked primary input, result and canonical
files are unchanged relative to the pulled revision. The four published primary
gains consequently remain 4.74%, 7.26%, 3.88% and 8.97%; cleanup is not a new
performance experiment. Exact reporting cleanup remains outside the recorded
optimization runtime.

The full multi-seed timed campaigns were not rerun during this audit. The new
short studies test orchestration and current algorithm execution; their counts
and timings do not establish that one method generally outperforms another.
Standard random-initialized NSGA-II still sometimes finds no feasible solution
under small budgets. Its documented exit code 2, empty archive and zero HV were
checked as valid search-failure reporting, not hidden as a success.

The held-out revalidation reports `source_snapshot_matches_current: false`.
Current differences are `cli.py`, `comparison.py`, `exact.py`, `examples.py`,
`generation.py` and `hybrid.py`. The recorded snapshots are intact and the live
model, evaluator and metrics match their frozen versions. See the
[complete revalidation record](../results/merged_final_audit/enhancement_reverification.json).
Use the frozen snapshots when reproducing historical timed algorithms; use a
fresh output directory and configuration for measurements of corrected code.

The older supplementary MOEA/D/exact-gap studies contain scalar result rows but
lack complete timetable archives and source manifests. Their arithmetic was
checked (96 and 120 rows respectively), but independent feasibility/front
revalidation is unavailable from those records. Older scalarization/cooling and
disruption results predate fixes and are labeled historical/exploratory. They
must not be presented as newly measured performance of corrected implementations.

All college data are synthetic. Medium/large observed trade-offs are empirical;
globally certified conflicts and ideal vectors are limited to the explicitly
documented small references. Calendar cover operations are dated administrative
exceptions; the repeating-week optimization retains its offering-consistent
teacher assignments and original three objectives.

## Reproduce the verification

From a clean checkout, use Python 3.12 and Node with npm:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python -m pip install -e .
python -m pip check
python -m pytest -q
cd frontend
npm ci
npm run build
cd ..

python experiments/verify_saved_results.py --study benchmark
python experiments/verify_enhancement.py --output work/reverification.json
```

The [CLI evidence](../results/merged_final_audit/cli_checks.json) lists all 55
invocations, expected exit codes and test budgets. The README's normal CLI and
experiment commands remain the supported entry points. Regenerate plots and
derived fronts in a disposable checkout if preserving every tracked output is
required. Resume only experiments created with the same source/configuration;
the cache correctly refuses incompatible historical records.

For website checks, start the API with a disposable database and Vite in separate
terminals, then run:

```bash
CLOCKWORK_DB=work/audit-campus.db CLOCKWORK_RUNS_DIR=work/audit-runs \
  python -m uvicorn api.server:app --host 127.0.0.1 --port 8000
# Separate terminal, from frontend/:
CLOCKWORK_API=http://127.0.0.1:8000 npm run dev -- --host 127.0.0.1
# Separate terminal, from the repository root:
python experiments/web_integration_check.py --api http://127.0.0.1:8000 \
  --web http://127.0.0.1:5173
python frontend/tests/browser_regression.py --web http://127.0.0.1:5173
python frontend/tests/browser_failure_regression.py --web http://127.0.0.1:5173
```

The browser scripts additionally require optional Python Playwright and Chromium;
see [frontend instructions](../frontend/README.md). These checks deliberately
publish schedules and create accounts in the disposable test database. They
must not target a database containing real campus records.

Machine-readable outcomes and captured logs are in
[results/merged_final_audit](../results/merged_final_audit/). Temporary environments,
screenshots, databases, build directories and caches are excluded from Git.
